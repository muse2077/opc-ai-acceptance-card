# 示例：文章摘要助手验收卡

> 示例用于演示如何填写，不是实际运行或测试报告。测试数据为虚构短句。

## 目标与范围
将用户提供的文章整理成便于快速浏览的摘要。仅生成草稿，不核实事实、不自动发布、不替用户作结论。

## 输入与输出
- 输入：用户有权处理的文章文本；测试前移除姓名、联系方式等个人资料。
- 输出：中文摘要 3 条，每条一句；保留原文核心信息，不补造原文没有的事实。

## 验收用例
| 用例 | 输入（脱敏/虚构） | 预期结果与检查点 |
|---|---|---|
| 1 正常文章 | “社区周六举办旧书交换。居民可带不超过五本书，活动上午九点开始，现场登记。” | 输出 3 条以内要点；准确包含周六、九点、最多五本及现场登记，不添加地点等原文没有的信息。 |
| 2 空输入 | 空白文本 | 不生成猜测摘要；明确提示“请提供文章内容”，等待用户补充。 |
| 3 敏感输入/失败 | 含虚构电话号码的文本；或服务不可用 | 敏感输入先提示删除/脱敏，不复述号码；服务失败时说明未完成、不伪造摘要，提示稍后重试。 |

## 人工确认与隐私
使用者逐条对照原文检查准确性、遗漏和语境后再采用。摘要可能误解或遗漏信息，不能当作事实核查。仅输入有权处理且已尽量脱敏的内容；不要放 API key、密码或个人资料，不要把私人文章贴入公开测试材料。

## 失败处理与结论
空输入要求补充；发现敏感信息则暂停并提示脱敏；模型/服务失败则停止输出并如实告知，不自动重试或发送。真实使用前由项目负责人在目标环境执行测试并填写实际结果；此示例没有实际运行记录。
